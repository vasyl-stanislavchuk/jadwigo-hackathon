# dl-5ssh.90: wave 2 plan, Jadwigo's look, a reading order and agent actions

Epic `dl-5ssh.90`. Wave label `wave:dl-5ssh.90-2`. docs.jadwigo.pl is live (wave 1) but wears stock
Starlight, its pages bury what they are for under how they are generated, and agents can read
`llms.txt` but not one page as Markdown. This wave themes the site from `@jadwigo/ui`, gives every
page one reading order, and adds a page-actions menu with a static `.md` per page.

## The order

1. Step 0 lands first. Until it merges, lane PRs target its branch or stay drafts.
2. The 3 lanes start once step 0 is pushed and run in parallel. Each adds only its own keys to
   `astro.config.mjs`, so a conflict there is a small merge, never a rewrite.
3. The agents lane takes `dl-5ssh.90.24` before `dl-5ssh.90.32`, because both change the host guard.
4. The owner publishes with the docs publish target once all 3 lanes land.

Stacks update by `git merge`, never by rebase. The lead takes the steward's hand-backs on every PR
of this wave.

## Risks the lanes check first

- Starlight switches on `data-theme`, and the night roles sit on `[theme="dark"]`. The theme lane's
  bridge copies one onto the other; a flash of day colours on a dark load means the script runs
  too late.
- `starlight-llm-actions` 0.13.0 peers Starlight 0.36 or later and Astro 5.6 or later; nobody has
  built it on Astro 7.4.2 here yet. Its `renderMarkdown: 'simple'` needs 8 optional packages. The
  fallback is `starlight-page-actions` 0.7.1 with `baseUrl` unset, and the lead decides.
- The starlight-openapi pages are injected routes with no `.md`; agents read `/openapi.json` there.
- `aws s3 sync` guesses a file's type from its extension; `.md` must arrive as `text/markdown`.

## Where it landed

All 3 lanes merged on 2026-10-30, the same morning as step 0. On `main`, a fresh build passes 181
docs tests and `check:dist`, and `dist/` carries a `.md` beside every hand-written and MCP page,
both alternate links in every page head, Andika in the CSS, and `/_llms-txt/` sets for api, mcp and
design-system. The owner publishes with the docs publish target; `.md` files upload as
`text/markdown; charset=utf-8`.

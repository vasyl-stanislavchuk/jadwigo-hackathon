# dl-uukj.32: wave 1 plan, Zeszyt everywhere

Epic `dl-uukj.32`. Wave label `wave:dl-uukj.32-1`. The owner saw the Grape purple `#7706ff` on the
parent's "Wyślij kod" button on 2026-10-29. Zeszyt's tokens (`packages/ui/src/styles/foundation.css`)
are scoped to `[data-lesson-theme]`, which only a lesson sets, so every non-lesson screen falls
through to the superseded `:root` palette in `tokens.css`. Wave 1 moves Zeszyt to `:root`, deletes
Grape, gives `packages/ui` the adult kit the parent screens need, and turns lesson-kit's copied
patterns into parts. Wave 2 (its own plan) then rebuilds the `apps/web` screens on that kit.

## The contract (what step 0 gives the lanes)

- **Two tokens** in foundation.css's type block: `--jw-size-target` (2.5rem, the big readout a task
  shows beside its figure) and `--jw-control-height` (3rem, a settings or navigation control).
- **Utilities** for every Zeszyt role and size (`tailwind.css` `@theme inline`): `bg-jw-act`,
  `text-jw-on-act`, `border-jw-line`, `text-jw-body`, `text-jw-target`, `min-h-kid-tap`,
  `gap-kid-choice`, `min-h-jw-control`, `rounded-jw-card`, `shadow-jw-act`, `duration-jw-step`, and
  `bg-kid-selected` for the picked state. Outside a lesson they resolve to nothing until the
  `tokens` lane lands; that is fine for an additive step.
- **`[data-picked]`** beside each `[class~="bg-primary/10"]` selector (foundation.css, stage.css), so
  the `kit` lane swaps the attribute for the class in one PR and the `tokens` lane deletes the old
  selector afterwards.
- **The check**: `@jadwigo/testing`'s `checkTokens` (`packages/testing/src/tokens.ts`), run by a
  `tokens.test.ts` in `apps/web/src` (one allowlist per lane directory: `play`, `review`, `parent`,
  `playground`, and the root's own files), `packages/ui/src` and `packages/lesson-kit/src`. A
  `tokens.allow.json` entry is `{path, snippet, why}`: `why` empty while the lane removes it, a
  reason when it stays. A stale entry fails, so the list only shrinks. The lane deletes the file
  when it is empty.
- **The app-page register** (T3 of the lead's plan): h1 `text-jw-prompt`, h2 `text-jw-instruction`,
  body `text-jw-body`, small `text-jw-small`, controls `min-h-jw-control`, the action button
  `bg-jw-act text-jw-on-act shadow-jw-act`, width `max-w-(--page-prose-max)`. The System page gets
  an "App pages" section in wave 2, where the owner confirms or vetoes it (`dl-uukj.32.7`).

## Shared paths

- `packages/ui/src/styles/**` changes only in the `tokens` lane; `packages/ui/src/index.ts` and the
  primitives only in `ui-parts`; `packages/lesson-kit/src/**` only in `kit`. A token a part needs
  and does not have is a message to the lead, who hands it to `tokens`.
- `kit` collides with live work: `dl-uukj.29.147` (owner UX rounds, in progress) and the audit
  fixes `dl-uukj.29.149` to `.157` edit the same parts (`.150` the spelling view, `.151` `scroll.ts`,
  `.152` ChoiceGroup and stage.css, `.155` StepShell and stage.css, `.156` and `.157` BarGraph and
  Bars). `kit`'s queue is ordered to start away from those files, merges `origin/main` before every
  PR, and keeps each PR to one pattern. Those issues carry a note that the check now fails a new
  literal.
- Lane PRs target `lead/dl-uukj.32-wave-1` until step 0 merges, then GitHub retargets them to
  `main`. Until then they stay drafts: the lead branch has no required checks, so a ready PR with
  auto-merge lands unreviewed (the kit lane's #194 did, and #192 carries it). A stack updates by
  `git merge`, never by rebase.
- The lead holds `md merge-steward inbox --wait` for every PR of the epic once the lanes stop.

## Stop rules for a lane

- A text pair that passed 4.5:1 under the lesson theme fails at `:root`: the primitives are wrong,
  not the scoping. Stop and tell the lead.
- A stage-size test, a family test you did not touch, or an e2e fails.
- A part needs a token that does not exist, or `apps/web` code to be meaningful.
- The same step failed 3 times with no new information.

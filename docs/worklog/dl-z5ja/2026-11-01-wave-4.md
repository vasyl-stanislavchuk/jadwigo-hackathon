# dl-z5ja: wave 4 plan, the parent's chat

Epic `dl-z5ja`. Wave label `wave:dl-z5ja-4`. Waves 2 and 3 have landed. The engine runs a turn
on Postgres, pgmq and Realtime behind the conversation routes, and `/playground/chat` drives it.
Wave 4 turns that into the parent's chat:
- where the chat lives;
- what it may say about a learner;
- consent before the first message;
- archiving a conversation;
- rating a turn.

It also clears the runner's review notes.

The milestone is the first real turn on jadwigo-dev. It waits on the owner's steps 3 and 4 (see
"What waits"). Nothing built here needs them.

## Decisions in force

- **`jadwigo-hackathon/decisions/2026-11-01-the-parent-s-chat-lives-in-a-side-panel-and-a-full-screen`**
  (`dl-42kc`, answering `dl-z5ja.33`). The side panel holds questions, on the learner page and the
  lesson screen, with the page as context. The full screen holds lesson building: the chat on the
  left and the lesson on the right.
- **`jadwigo-hackathon/decisions/2026-11-01-deleting-a-conversation-archives-it-kept-for-the-pod`**
  (`dl-84wo`, answering `dl-z5ja.34`). A parent's delete archives the conversation: it is hidden
  from the list, kept for the pod, and deleted with the pod. No "delete for good" is built.
- **`jadwigo-hackathon/decisions/2026-11-01-a-learner-s-data-names-included-may-reach-any-meta-model-the-con`**
  (`dl-uafq`). A learner's data, names included, may reach any Meta model, the contributor model
  included. It supersedes `dl-2uq1`'s no-training rule. Tests still use made-up learners, because
  the repo fence stands.
- `dl-z5ja.27`, answered: the chat may say everything the record holds (goals, status words, the
  brief, mistakes, the child's answers and words), each claim cited. It gives no levels, scores,
  comparisons or diagnoses.
- Still drafts for the owner to accept: `dl-j2k8` (the engine is Supabase-native), `dl-l1cc`
  (wave 2 and 3's lane re-cut) and `dl-wlap`.

## Lead decisions

35. **This wave has no contract step 0.** Each lane edits the contracts its issue names in its own
    PR: `run.ts`, `routes.ts`, error types, snapshots, `openapi.json` and the terraform route keys.
    It declares each snapshot change as a one-way door in its PR body. Wave 3's decision 31 set
    this pattern for the api lane. A contract PR merges `origin/main` just before it goes ready,
    because contract PRs conflict on `openapi.json`. When 2 lanes need the same file at once, the
    lead orders them.
36. **The side panel's page context travels on the message** (`dl-z5ja.107`).
    `ConversationMessage` and the inbox's `message` payload gain an optional `context`: a learner
    id or a lesson id. The runner reads it pod-scoped, and a context id from another pod is
    refused with no model call. It is not a steer source, because a steer joins a running turn and
    a context starts one.
37. **A rating lands in its own table, `run_rating`** (`dl-z5ja.110`), behind
    `POST /api/v1/runs/{id}/rating`. It does not go to an analytics event, because a Bad note may
    hold learner data. It does not go to `run_event`, which is the runner's log. Try again is no
    route: the page resends the parent's last message.
38. **`dl-z5ja.102`, the answer check:**
    - A refused answer is re-checked only against events up to its call's last `seq`.
    - Parent messages from earlier turns of the same conversation count as given, so `prior.said`
      stays.
    - Words beside a failing tool call stay dropped, and a scenario freezes that.
39. **Consent is the pod's, kept on the server** (`dl-z5ja.112`). `pod.ai_consent_at` is set and
    withdrawn by a parent, and the conversation routes answer `AiConsentMissing` while it is null.
    The screen (`dl-z5ja.32`) states `dl-uafq` as it is: the data reaches Meta's models, which may
    train on it; run events live until the pod is deleted; an archived conversation stays with the
    pod.
40. **`dl-z5ja.71` comes before `dl-z5ja.25`.** The lead lands the per-verb view schemas for the 5
    lesson verbs. The knowledge lane then adds its 5 verbs to `VerbName` and their view schemas in
    the same file, under decision 35.
41. **`dl-z5ja.76` splits.** The runner lane takes the steer's optional `patch`, a JSON merge patch
    on the lesson file, and `runStep` applying it as a `lesson_revision` with no model call. The
    web lane takes the pane's half (`dl-z5ja.111`).

## Briefs

The wave 1 to 3 rules apply:
- a lane's brief is its issue, and each lane gets its whole queue at once;
- one PR per issue, titled `<id>: <what>`, targeting `main`;
- `gh pr ready` and `gh pr merge --auto --squash` once it is ready for review;
- a stack updates by merge, never by rebase;
- after the steward drafts a red PR, re-ready it once the fix is pushed;
- notes on the issue say what ran and what didn't;
- a lane ends with `DONE`, `DONE_WITH_CONCERNS`, `NEEDS_DECISIONS` or `BLOCKED`;
- paid calls and anything that ships to an environment are the owner's, each one command to type
  with `!`.

Done when:
- every issue in the lanes' queues has merged;
- `make check-all` is green on `main`;
- a component test shows the panel sending a learner context and the full screen opening the same
  conversation;
- a scenario shows a parent patch applied with no model call.

Not run by the lead: Playwright (CI), paid calls and anything that ships to an environment (the
owner, by a prepared script).

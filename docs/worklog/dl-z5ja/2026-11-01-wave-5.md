## Lead decisions

42. **Wave 5 has a contract step 0** (`dl-z5ja.11.1`, this PR), unlike decision 35. Four lanes
    build on the same shapes: `AttachmentId` (`atch_`, since `att_` is the attempt's),
    `Attachment` (the table's row), `MessageAttachment` (a message's storage reference, renamed from
    the old `Attachment`), `AttachmentCreate`, `AttachmentUpload`, `AttachmentRead`,
    `ConversationMessage.attachment_ids`, `LIMITS`, 4 error types and 2 routes. Only step 0 edits
    them. The one exception: `dl-e8ov.2.22` adds `attachment` to `RECORDS` in `tables.ts` with its
    migration, because the naming test ties a record to its table.
43. **Uploads are scoped to the pod, keyed by random ids, and checked when the message is sent.**
    This is md drop-comments' handshake:
    1. `POST /api/v1/attachments` writes a pending row and returns a presigned S3 form for
       `pending/<pod>/<id>`, bound to the key, `image/jpeg` and the exact size.
    2. The page posts the file straight to S3.
    3. `postMessage` with `attachment_ids` checks each one: the stored size, the JPEG's first bytes,
       and no Exif. It copies each to `pods/<pod>/attachments/<id>.jpg`, then flips the rows and
       writes the inbox row in one transaction.

    A photo may have no learner ("Bez dziecka") and comes before any conversation, so it is
    scoped to the pod. There is no `/done` call and no homework table. S3 deletes what was never
    sent after 1 day.
44. **`apps/api/src/conversations.ts` goes in order.** The platform lane's `dl-z5ja.116` and
    `dl-z5ja.114` go first. The uploads lane keeps its code in new files and replaces step 0's
    guard in `postMessage` (a message with photos is 409 `AttachmentMismatch`) with one call, last,
    after merging `origin/main`.
45. **Engine image input is built and tested on recorded responses**, as decision 33 did for
    `HttpMuse`. The live call waits on the owner running the `dl-z5ja.3` image probe.
46. **Nothing waits on `terraform apply`.** The API and the runner read `UPLOADS_BUCKET` through an
    S3 port, with an in-memory fake in tests. The owner runs the apply after `dl-z5ja.11.2` merges.
47. **Only JPEG is stored in wave 5.** PDF, DOCX and the read-back are wave 6 candidates.
48. **The web work splits by file age.** `dl-z5ja.11.5` is the upload helper and `AttachmentChips`, in
    new files under `apps/web/src/chat/attachments/`, and starts now. `dl-z5ja.11.9` turns photos
    on in `NewLessonBox` and passes `attachment_ids`. `dl-z5ja.11.6` draws the thread's thumbnails.
    Those 2 wait for `dl-z5ja.108`, which moves the chat.
49. **A parent may pick any photo; the store sees only JPEG.** The page decodes each photo with
    `createImageBitmap` (orientation applied) and re-encodes it to a JPEG: at most 2000 px on its
    long edge and 4 MB, with EXIF and GPS dropped. HEIC is handled like this:
    - iOS Safari already hands a JPEG to `accept="image/*"`, so the input never names `image/heic`.
    - Safari 17+ decodes HEIC itself.
    - On Chrome, Firefox and Android, a lazily loaded `libheif-js` chunk decodes it.
    - If decoding still fails, the photo is refused with a plain line.

**Why the cut holds:**
- The bucket, the table, the store and the API are one sequence in one lane: the API needs the other 2, and each is small.
- The 2 new lanes start in new files only.
- The engine's edits stay in the runner lane's own paths, so no second lane touches `run-step.ts`.
- `conversations.ts` is ordered by decision 44.

**Who takes hand-backs once the lanes stop:** the lead, then the shepherd (`md shepherd status`).

## Briefs

The wave 1 to 4 rules apply:
- a lane's brief is its issue, and each lane gets its whole queue at once;
- one PR per issue, titled `<id>: <what>`, targeting `main`;
- `gh pr ready` and `gh pr merge --auto --squash` once the PR is ready for review;
- a stack updates by merge, never by rebase;
- notes on the issue say what ran and what did not;
- a lane ends with `DONE`, `DONE_WITH_CONCERNS`, `NEEDS_DECISIONS` or `BLOCKED`;
- paid calls and anything that ships to an environment are the owner's, each one command to type
  with `!`.

Done when:
- every issue in the lanes' queues has merged, and `make check-all` is green on `main`;
- an api int test sends a photo-only message whose inbox row carries the stored
  `MessageAttachment`, while a JPEG with Exif and another pod's id leave nothing;
- a `jadwigo-ai` scenario shows the image part on the turn and a placeholder on the next turn;
- a web component test shows the first screen uploading, holding the send while a photo uploads,
  sending `attachment_ids`, and the thread swapping the local thumbnail for the stored one.

Not run by the lead: Playwright (CI), paid calls, and anything that ships to an environment.

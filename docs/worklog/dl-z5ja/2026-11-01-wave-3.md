# dl-z5ja: wave 3 plan, the adapters

Epic `dl-z5ja`. Wave label `wave:dl-z5ja-3`. Wave 3 swaps the engine's in-memory adapters for real
ones: Postgres, pgmq, Realtime, `HttpMuse` and the step host. It runs in parallel with wave 2
(`2026-11-01-wave-2.md`), which hardens the engine while it stays engine-neutral. After the lane
re-cut below, the 2 waves touch disjoint paths, and the owner's gates sit on wave 3 lanes only.

Some of wave 3 landed before this plan was written, and before the engine decision was recorded:
7a, the run tables and `jadwigo_runner` (`dl-z5ja.7`, #418); 7b, the pgmq `agent_step` queue, the
cron sweep and the broadcast (`dl-z5ja.52`, #421); and `PostgresStore`'s run methods and
`PgmqRunQueue` (`dl-z5ja.19`, #422 and #424). A merge deploys nothing, so the order costs nothing.

Read first:
- `docs/worklog/dl-z5ja/2026-11-01-wave-2.md`, its Lead decisions 20 to 26 and its amendments.
- `packages/jadwigo-ai/AGENTS.md`: the engine's rules, the learner-data rule included.
- `supabase/README.md`: migrations, the shim and the pgTAP tests.

## Lead decisions

Recorded as `jadwigo-hackathon/notes/2026-11-01-engine-waves-2-and-3-run-in-parallel-on-re-cut-lanes`
(draft decision bead `dl-l1cc`). The owner confirmed 27, 28 and 33.

27. **Waves 2 and 3 run in parallel.** Wave 2 is engine-neutral hardening; wave 3 is the adapters.
    After the re-cut they touch disjoint paths.
28. **Wave 2 step 0 carries the steer's 2 one-way doors** (`dl-z5ja.51`): a migration that adds
    `steer` to `run_event_type`, with a pgTAP case, and the `vitest -u` update of
    `schemas/run-event.json` and `schemas/run-inbox.json`. 7a snapshotted `run.ts` and made the
    type an enum, so no logged steer avoids them.
29. **`packages/jadwigo-ai/src` is cut by folder:**
    - `run/**` and `fence/**`, the runner lane (wave 2);
    - `verbs/**`, the verbs lane (wave 2);
    - `muse/**` and `config.ts`, the muse lane;
    - `queue/**`, the queue lane.

    `scenarios.test.ts` and the `index.ts` exports are the lead's. A lane asks for an export in
    its PR body, and the lead approves it there. `dl-z5ja.35`'s contributor-tier names test moves
    to `dl-z5ja.18`, where the TypeScript port of `jw.pii.guard` lives: `GuardedMuse` never reads
    `request.names` today.
30. **`dl-z5ja.21` splits.**
    - 21a is the conversation routes (api lane, `dl-z5ja.21`) and the `realtime.messages` join
      policy (queue lane, `dl-z5ja.61`).
    - 21b is the page's transport swap (web lane, `dl-z5ja.65`), last in the web lane's queue,
      after 21a and `dl-z5ja.59`.
    - `dl-z5ja.59` (the broadcast sends ids only) lands before 21b. The page treats a broadcast as
      a poke and fetches the events after its cursor, so `mergeLive` and `foldRun` stay as they are.
31. **The api lane may edit, for the conversation routes only:** `packages/contracts/src/routes.ts`,
    `openapi.json`, the route lists in `infra/terraform/main.tf`, and the `apps/docs` API pages. It
    runs `make check-all`, because a `ROUTES` change needs it.
32. **`runStep` takes the sweep path for a due run before any model call** (`dl-z5ja.60`, wave 2's
    runner lane). It is frozen as the scenario "a due run enqueued by the sweep ends without a
    model call". 7b's cron enqueues every due run expecting it, and today `runStep` checks only the
    max deadline.
33. **`HttpMuse` (`dl-z5ja.18`) is built and unit-tested on recorded responses** before `dl-z5ja.22`
    is answered. The owner-run live call and `make engine-smoke` wait on `dl-z5ja.3` and
    `dl-z5ja.22`. No learner data leaves the repo in the build.
34. **The step host's home is `apps/runner`** for a 2nd Lambda, or `supabase/functions/agent-step`
    for an Edge Function, and `dl-z5ja.5` picks. Its invocation path is part of `dl-z5ja.20`: the
    API Lambda invokes the host after `pgmq.send`, and the 30 s cron is the safety net. There is no
    `pg_net` call anywhere today.

  after `dl-z5ja.42`; `dl-z5ja.65` (21b) comes after `dl-z5ja.21` and `dl-z5ja.59`; the host lane
  comes after the muse and queue lanes.

- Routes authorize with `getRun` under the claims' pod, where RLS answers NotFound, never with

- `packages/jadwigo-ai/src/index.ts` exports neither `PgmqRunQueue` nor `GuardedMuse`, and the step
  host needs both. The queue and muse lanes ask for the exports in their PR bodies.
- The broadcast sends the whole event today, the parent's text included. `dl-z5ja.59` makes it
  ids only.

## Briefs

The wave 1 and wave 2 rules apply:
- a lane's brief is its issue, and each lane gets its whole queue at once;
- one PR per issue, titled `<id>: <what>`, targeting `main`;
- `gh pr ready` and `gh pr merge --auto --squash` once it is ready for review;
- a stack updates by merge, never by rebase;
- notes on the issue say what ran and what didn't;
- a lane ends with `DONE`, `DONE_WITH_CONCERNS`, `NEEDS_DECISIONS` or `BLOCKED`;
- paid calls and anything that ships to an environment are the owner's, each one command to type
  with `!`.

Done when:
- #424, `dl-z5ja.59`, `dl-z5ja.56`, `dl-z5ja.21`, `dl-z5ja.18` and `dl-z5ja.48` are merged;
- the migrations and pgTAP tests are green with the join-policy and ids-only cases;
- `bunx turbo run test test:int --filter=./apps/api` is green;
- `dl-z5ja.20`'s host has its `FakeMuse` unit test, and `make engine-smoke` passed once, run by the
  owner, with its output on the issue;
- `dl-z5ja.65` (21b) runs one turn on jadwigo-dev, once the owner ships it there.

Not run by the lead: Playwright (CI), paid calls and anything that ships to an environment (the
owner, by a prepared script).

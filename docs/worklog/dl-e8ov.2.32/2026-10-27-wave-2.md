# dl-e8ov.2.32: wave 2 plan, v0 runs on Supabase

Epic `dl-e8ov.2.32`. Wave label `wave:dl-e8ov.2.32-2`. Wave 1 plays a lesson from the local Postgres
(`2026-10-27-wave-1.md`, in the lead's PR). Wave 2 puts the same model on real Supabase: 2 projects
in Frankfurt, local and CI made to match them, migrations pushed by the owner, and the playground
played once against the cloud dev project.

## Decisions in force

All of these are under `jadwigo-platform/decisions/`:
- `2026-10-27-jadwigo-runs-on-a-prod-and-a-dev-supabase-project-a-native-local`
  - Local Postgres.app is the default for everything that can match Supabase.
  - `jadwigo-dev` is for auth, Supavisor and the last check before prod.
  - The owner runs `make db-push`.
  - `apps/api` connects through the Supavisor transaction pooler, with prepared statements off.
- `2026-10-27-jadwigo-s-supabase-projects-are-recreated-in-frankfurt-and-sign`: prod and dev are
  recreated in eu-central-1, the Ireland project is deleted, and each project signs with an RS256
  key, because API Gateway's JWT authorizer accepts only RSA.
- In force already: `2026-10-26-jadwigo-s-records-live-in-supabase-postgres-in-place-of-dynamodb`,
  `2026-10-27-sql-migrations-are-the-source-of-truth-for-jadwigo-s-schema`,
  `2026-10-26-a-green-merge-does-not-deploy-to-prod-the-owner-deploys-manually`.

# dl-9t2o: wave 1 plan, Polish and English live on jadwigo.pl, the app and lessons

Epic `dl-9t2o` (meta, `project:jadwigo-hackathon`). Wave label `wave:dl-9t2o-1`, lanes `lane:i18n-*`.

Jadwigo goes live in Polish and English for the hackathon. Every issue keeps its own workstream's
parent and label; this epic only ties the wave together.

Wave 1 builds 3 things:
- every jadwigo.pl page in Polish and English, under `/en/`;
- screens that follow the language a parent picks;
- English lessons that grade in English.

Wave 2 switches English on and lands the English featured lessons.

Read first:
- the decisions below;
- `docs/runbooks/add-a-language.md`;
- `packages/config/src/languages.ts`;
- the drop `jadwigo-i18n`, which is the research behind this. Its open questions are answered now.

## Lead decisions

1. **Step 0 (`dl-9t2o.1`) is the only contract change in wave 1.**
   - `Language` is `["pl","en"]`.
   - `tools/src/check-languages.ts` now fails when the contracts enum or packages/copy's `Language`
     type lists other codes than `languages.ts`. Apps import `LANGUAGE_CODES` from
     `@jadwigo/config`.
   - The database's `language` type keeps `uk`, because no row uses it and dropping it is a
     migration nobody needs yet.
2. **No new route in wave 1.**
   - The parent's language is `AccountCreate.language`, picked at sign-up with pl preselected,
     stored as `Pod.language`.
   - The screens' language is the parent's pick, kept in the browser between visits.
   - Changing a pod's language after sign-up needs a `PATCH` route. That is wave 2 and the lead's
     contract change.
3. **Paraglide lives in `packages/copy`.**
   - The project is `project.inlang` (pl is the base).
   - The messages are `messages/{pl,en}.json`, and their review flags are
     `messages/review.{pl,en}.json`.
   - `bun run messages` compiles them into `src/paraglide`. That folder is committed, generated, and
     ignored by Biome and knip. Recompile it after every message change and commit the result.
   - Import it as `@jadwigo/copy/messages` (the message functions) and `@jadwigo/copy/runtime`
     (the locales).
4. **The key prefix splits `packages/copy` between lanes.**
   - `site_*` messages are i18n-site's.
   - Every other message and the typed tables are i18n-copy's.
   - Step 0 seeded the site's 404, switch and note keys, plus the app's `parent_language*` table
     keys.
   - i18n-app never edits `packages/copy`. A missing key is a message to the lead.
5. **Marketing words stay in content.** The site's long text stays in its content collections
   (`src/content/{pl,en}`). Paraglide holds the site's UI strings only.
6. **English is drafted in English.** English copy, lessons and checklists are written as English,
   not translated word for word. Each line ships `reviewed: false` until the AI reviewer with
   `workflows/_lang/en/checklist.md` passes it.
7. **A lane never edits another lane's paths, a contract or a dependency.** Each of those is a
   message to the lead. The lead answers with a step-0 follow-up PR that lanes merge in.

**Why the cut holds:**
- Step 0 makes the only contract and shared-dependency change.
- The site and copy lanes split `packages/copy/messages` by key prefix.
- The app lane reads copy and never writes it.
- The lessons and core lanes share no files.

**The one shared seam is grading.** Lessons hold English answers, and core grades them. Core
exposes `packages/core/src/lang/<lang>` behind the grading functions' existing signatures, so
the lessons lane needs nothing new from it.

**What runs alongside.** The `dl-z5ja` wave 2 web lane also adds chat keys to the copy tables.
Before i18n-copy runs its codemod, it merges `origin/main` and re-runs the codemod, which gives the
same output when run twice.

## How a lane runs

- The lead opens each lane:
  `md worktree new i18n-<x> --repo jadwigo-hackathon --project jadwigo-<workstream> --bead <first> … --launch`.
- The lane works `bd ready --label lane:i18n-<x>` in queue order: one issue, one PR.
- Each PR is titled `<id>: <what>` and starts as a draft. Its base is `lead/dl-9t2o-step0` until
  step 0 merges, then `main`. When it is ready: `gh pr edit <n> --base main`, then `gh pr ready`,
  then `gh pr merge --auto --squash`.
- The lane parks `md merge-steward inbox --wait` in the background and fixes its own hand-backs.
- **Once the lanes stop, the lead owns every PR's hand-backs.**

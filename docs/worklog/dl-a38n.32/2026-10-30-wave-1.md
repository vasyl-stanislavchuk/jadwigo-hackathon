## What the handoff got wrong, and what this plan does instead

The handoff (`docs/worklog/dl-a38n/2026-10-30-handoff-bank.md`) asked for an import in
`packages/bank` and a `render_ok` filter on search. Neither fits the code: `packages/bank` is the
search client and `bankContract`, all ingestion is `jadwigo-bank`, and search rows are sets
(`SearchRow.id` matches `^set_`), so no per-item flag can ride on them. The 2026-10-30 run (#319)
found 0 error-level findings on 670 items, but it measured 2 animation frames after mount while
`render-picture-missing` skips a still-loading image, so none of the 399 items with pictures were
checked. The gate is rebuilt from the source outwards:

```
jadwigo-bank/tools/khan                                     jadwigo (this repo)
to_family_pl ─► converted-pl.json ─► bun tools/conformance/run.ts (page: strict, judge, render)
             ◄─ sidecar + <bank repo>/refusals/pl.json merged into each item's status
sync derive  ─► questions/khan/<id>.json carries status per variant
build_sets   ─► set pages: items.ready_ids {pl,en}, items.count.ready {pl,en}; 0-ready sets not indexed
                                                             jw load_item / draw refuse anything not plays+checked_at
                                                             jw question refusals / assign / flag: the loop
```

## The verdict: the converter's `status`, extended

```
{kind: "plays", rules_version, checked_at}                       ready
{kind: "waiting", issue, reason}                                 the converter cannot make it yet (today)
{kind: "refused", rule, text, fix, issue?, rules_version, checked_at}   failed a check; issue = the shape's bead
{kind: "flagged", by, reason, issue?, on}                        a person pulled it
```

A `plays` with no `checked_at` is `not checked`, and jw refuses it. The verdict is per language
variant. The sidecar beside the items file stays `<items>.render.json` (`tools/conformance/report.ts`).
The refusals file, `<JADWIGO_BANK_DIR>/refusals/<lang>.json` (the bank repo checkout, committed there), holds `{shapes: [{rule, question_type, issue}],
flags: [{id, by, reason, issue?, on}]}`: ids and reasons only, so it is safe in git.

## The order

1. Step 0 lands first. Lane PRs target its branch or stay drafts until it merges.
2. The three lanes start together; their paths are disjoint (two repos, and `apps/cli` against
   `apps/web` + `tools` in this one).
3. jw's items 1 and 2 go ready only after the owner's stamp run: before it every real item is
   `not checked` and the first real lesson (`dl-e8ov.5.38.5`) would draw nothing.
4. The runner's re-run (item 4) follows its item 3; the lead files one bead per new shape from it.
5. The owner re-publishes last; the drop is refreshed after.

Stacks update by `git merge`, never by rebase. The lead parks on `md merge-steward inbox --wait` and
takes every hand-back once the lanes end. The builder never reviews its own work: the lead re-runs
each lane's "done when" before `gh pr ready`.

## When something isn't ready: the loop

1. The stamp report groups refused variants by `(rule, question_type)`, a shape. Routing: `render-*`
   to lesson-kit (`dl-a38n.28`); `contract`, `key-grades` to the converter; `render-picture-missing`
   to the media pipeline; `flagged` to whoever flagged.
2. `jw question refusals --new` lists shapes with no bead; the lead files one per shape under `dl-n9fr`
   and writes it back with `jw question refusals assign`. The next stamp carries the `issue`.
3. `jw question flag <id> --lang pl "<why>"` pulls an item the rules missed; jw reads the flags file,
   so the next draft leaves it out before any re-run. `lesson_edit` fixes the copy; the flag tells the source.
4. Re-admission is automatic: a fix lands, the nightly stamp flips the variant back to `plays`, the
   report prints `re-admitted` by rule, and `--since <bead>` shows whether a closed bead emptied its shape.
5. Nothing is silently dropped: `plays + waiting + refused + flagged = items`, asserted by the hook's test.

## Languages

Polish first, English second, one shape. Every new field is keyed by language (`ready_ids.pl`,
`count.ready.pl`, the variant's `status`), the page draws each item in its own copy, and the runner
takes `--lang`. Polish is gated end to end in this wave. English is the same runner over
`converted.json` as a nightly job when English lessons open: one more file, no new code.

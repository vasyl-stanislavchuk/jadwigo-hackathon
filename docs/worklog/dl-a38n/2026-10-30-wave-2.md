## Lead decisions

1. **The render check runs in the page on the real DOM**, never in happy-dom (no layout there; it
   could not see the live-run bug). Rules are pure functions over a step's root `Element`,
   `renderFindings(root, step): Finding[]` in `apps/web/src/playground/lesson/render/rules.ts`; the
   page runs them after each step draws and POSTs `{draft_id, findings}` to `/@builder/render`
   (`apps/web/dev/render.ts`), which writes `<draft_id>.render.json` and pushes it with the draft.
2. **jw reads `render.json`**: `lesson_check` and `lesson_edit` return render findings beside the
   check's when the file exists, so the agent sees them without a browser.
3. **Conformance drives the real page**: `/playground/conformance` draws items from a local JSON
   file through the lesson adapter and runs the same rules; `tools/conformance/run.ts` starts the
   web dev server, opens the route in headless Chromium (playwright is already apps/web's
   dependency), and writes the report and the sidecar. By hand and nightly, never in `make check`.
4. **The gate is the bank session's** (`dl-a38n.32`, handoff above): conversion, import, index,
   search, draw and backfill. Its runner is `dl-a38n.31` in this repo.
5. **Lane PRs target `main`**; ready and `--auto` as soon as they are ready for review (`dl-03l2`); confirm the auto flag after
   any retarget or draft toggle (`dl-5ssh.101` is still open).

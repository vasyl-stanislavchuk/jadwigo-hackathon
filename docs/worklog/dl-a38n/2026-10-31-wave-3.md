# dl-a38n: wave 3 plan, one request to a verified play link in under 60 seconds

Epic `dl-a38n`. Wave label `wave:dl-a38n-3`. The second live run (2026-10-31, draft
`draft_b5226c2163d7`) gave a clean card in 72 s with 0 tool errors, and then took 6 minutes and
3 imports into 3 databases before a play link, never confirmed. 55 of the 72 s were the model
reading a 36 KB draft result and writing 8.9 KB of twins and mistake cards; 6 of 12 twins lost
their pictures and the check passed them; 58 `left_out` lines came from set pages and the
converted file disagreeing. This wave makes the operator's flow one request to a verified play
link, under 60 s, with no manual step, and makes the guards catch what the run let through. The
parent-facing experience (a parent asks in the app, a hosted composer) is the wave after; this
wave builds only what it reuses as is.

## Lead decisions

1. **One local database.** `LOCAL_DATABASE_URL` in the Makefile (`postgresql://localhost:$PGPORT/jadwigo`)
   is what `make dev`, `make db-reset` and `make lesson-import` use; `LOCAL_DB_GATE` refuses
   anything but a localhost jadwigo* database. `.env.local`'s `DATABASE_URL` keeps naming
   `jadwigo_test` for the integration tests. Closes `dl-5ssh.112`. Landed in step 0.
2. **jw publishes through make.** `lesson_publish(draft_id, target="local")` runs
   `make -s lesson-import FILE=<draft> JSON=1` in `JADWIGO_REPO_DIR` (step 0 gave the import a
   `--json` output: `{file, lesson_id, version, version_id, published, assignment_id, play_path,
   questions}`), then verifies: `GET /api/health` 200, `POST /api/v1/assignments/{id}/attempts`
   with mode preview 201 and `plan.length == questions`, web `/play/<id>` 200. It writes
   `<draft_id>.publish.json` (`{draft_id, request, lesson_id, version, assignment_id, play_url,
   verified, target, published_at, timings}`) and returns it with an absolute `play_url`.
   `target=dev` refuses with the owner's make line; prod always refuses. Hosts mirror
   `tools/src/ports.ts` DEV_PORTS; overrides `JW_LOCAL_API_URL`, `JW_LOCAL_WEB_URL`, env only.
3. **The twin is a sibling bank item.** In `draft()`, after the times rule: the same set, the same
   `problem_type`, family and `question_type`, the same representation signature, a different
   key, not already in the lesson; chosen deterministically; copied with its hints, credit and
   `based_on: {question: "khan:<id>"}`. `_to_write` lists no twin for it; the card says
   `twin_source: bank khan:<id>` or `written`.
   **The representation signature**, defined once here, held authoritatively in `check.ts` and
   mirrored in jw: the count of picture objects (`src` + `alt` + `width`) at any depth plus
   `stem.image`; the figure `kind` under any `figure` key; the sorted set of option
   `content.kind`; the `input` kind.
4. **Mistake cards come from the item.** The bank pass writes `help.boost_by_mistake` per core
   class onto each converted item; `_to_write` lists `boost_by_mistake` only for classes the item
   lacks. The player already falls back to `look` for a missing class.
5. **Incremental check.** `lesson_check` rebuilds only the steps sent in `help`; a step left out
   keeps the file's words, the bank twin and `lesson_edit` changes. Every agent word goes through
   `pii.guard` (`dl-a38n.36`); `lesson_edit` refuses a non-object patch before merging
   (`dl-a38n.35`).
6. **Payload budgets.** Draft result ≤ 8 KB and check result ≤ 6 KB on the 12-question fixture,
   asserted by pytest: `left_out` as `{total, by_cause: [{cause, count, examples[3]}]}` plus a
   `setup_warning` when over 20% of drawn ready ids are missing from the converted file; copied
   rungs only when `you_write` names a rung or `verbose`; the card without `left_out`, TeX made
   plain (`dl-e8ov.5.38.6`), rungs only with `full`; the check result without `import_command`,
   warns as `{rule: count}`.
7. **New rules live in check.ts, not the render rules**: they are properties of the file's data
   and gate every `lesson_check` with no page open. `twin-representation` (error),
   `twin-same-picture` (warn), `key-grades` (error, `judge` and `solutionOf` from core, the edge
   step 0 allowed). Compile keeps a twin's `credit` and `based_on`; no snapshot moves.
8. **A clean machine works.** `jw doctor` (CLI and MCP) and `jw bank pull`; `JW_KHAN_CONVERTED`
   stays unset; `apps/cli/.env.example` names the real default.
9. **No contract change this wave.** `<draft_id>.publish.json` already carries the shape of a
   future `LessonRequest`; the learner-linked assignment is an additive join record when the
   next wave builds it, never `Assignment.learner_id`.
10. **Timing is measured.** jw stamps each tool call's `called_at` and `returned_at` into its
    state; `jw lesson timing <draft_id>` prints the split; `smoke_ready --live --publish` prints
    seconds per stage. Budget: draft ≤ 8 s, model writes ≤ 25 s, check ≤ 5 s, model reads the
    card ≤ 5 s, publish ≤ 5 s, slack 12 s.
11. **A lane PR targets `main`.** One stacked on step 0 goes ready once it is ready for review:
    `gh pr edit <n> --base main`, ready, auto (`dl-03l2`, `AGENTS.md` "Lanes and waves").

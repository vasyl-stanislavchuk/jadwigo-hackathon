## Scope

A reader of converted Khan items by id, from a file outside git, surfaced as a verb and a tool.

- `apps/cli/src/jw/items.py`: `load_item(item_id, language="pl") -> dict`. The file comes from the
  setting `JW_KHAN_CONVERTED` (add it to `settings_keys.py` with a comment in that file's style).
  Default when unset: `<KHAN_DIR>/converted-pl.json` if it exists, else `<KHAN_DIR>/converted.json`,
  where `KHAN_DIR` is `~/projects/david-learns/media/khan` (the parsed pull; name that default in
  `settings_keys.py` too). Read the file once per process (cache), never from git.
- The file's shape, on the owner's machine (do not read the real file in a test; the shape is all
  you need): `{"generated_by": ..., "licence_note": "<text>", "items": [ {...}, ... ]}`. An item:
  `id, family, problem_type, grade, language, question{text, pictures}, spec{data, family, help,
  id, key, phase, question_type, say}, credit{checked, original_lang, ref, source, url}`, plus
  course fields (`exercise`, `exercise_title`, `lesson_title`, `unit_title`, `order`, `source_url`,
  `status`). `spec` is the family step `packages/lesson-import/src/lesson-file.ts` wants in a
  lesson file's `question` (family, data, key, help) plus `say` and `question_type`.
- What `load_item` returns: the composer's view, so the key and help stay in. Shape:
  `{"id", "language", "family", "problem_type", "question_type", "say", "question": {"family",
  "data", "key", "help"}, "credit": {...}, "based_on": {"question": "khan:<id>", "changes": []},
  "course": {"exercise_title", "lesson_title", "unit_title", "order"}}`.
  `credit` is the contract's `Credit` (`packages/contracts/src/records.ts`): `source, ref, url,
  licence, original_lang, checked`. The converted file's credit has no `licence`: take it from the
  item when present, else from the file's top-level `licence_note`, and raise a `JwError` when
  neither has one (lead decision 4).
- Errors are `JwError` with a hint naming the setting to fix: the file is missing (hint: set
  `JW_KHAN_CONVERTED`, or run the Polish conversion, bead `dl-e8ov.5.38.1`); the id is not in the
  file (hint: the file's path and item count); the item's `language` is not the one asked for.
- `jw question item <id> [--language pl] [--json]` in `commands/question.py`, the same pattern as
  `show`: a shared function `item_view(item_id, language)` that the verb prints and the tool returns.
- `question_item(item_id: str, language: str = "pl")` in `commands/mcp.py`. Add it to `TOOLS`.
  The docstring is what the calling agent reads: say it is the composer's view with the key and
  help, never shown to a child.

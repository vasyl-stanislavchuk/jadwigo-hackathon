This page is for anyone writing a lesson or building a question: how a question is put together,
and every question type there is.

A question is built in 2 steps. A lesson author picks an **interaction family**: what the learner
does, such as choose, type or put in order. Then a **question type** of that family sets its
options, such as a true-or-false layout or a typed number on a keypad.

The family decides the shape of the answer and how it is checked. The question type decides how
it looks. So 2 question types of one family are checked the same way.

## Status

- **refined**: its design is settled.
- **draft**: it plays, but it is still being worked on.
- **idea**: it is only proposed.

## After a miss

A question type either marks the parts the learner missed, so they fix only those, or marks the
whole step. A miss is shown in red pen, and the words follow the rule in
[Copy](/design-system/copy/#a-child-never-reads-a-bare-wrong).

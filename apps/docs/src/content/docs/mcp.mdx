This page is for anyone connecting an AI agent to `jw mcp serve`, Jadwigo's MCP server: how to
register it, how an agent drafts a lesson with it, and every tool it gives.

The server speaks MCP on stdio. An agent uses it to search the question bank and to draft a lesson
for a parent. Each tool calls the same function as a `jw` command, so a tool's JSON is that
command's `--json` output. A call that fails comes back as a tool error. Its text is the error and
a hint.

## Register the server

The server runs from a checkout of the repo through `uv`. It finds the bank's URL and token in
`~/.config/jadwigo-bank/bank.env`. `JADWIGO_BANK_DIR` can sit in that file too, in place of the
`env` entry. Replace the 3 paths below with your own.

### Claude Code

Put the name before the `-e` flags, and give each variable its own `-e`. The flag takes every
value up to `--`, so a name after it is read as a variable.

```sh
claude mcp add --scope user --transport stdio jadwigo \
  -e JADWIGO_BANK_DIR=/path/to/jadwigo-bank \
  -e JW_KHAN_CONVERTED=/path/to/converted-pl.json \
  -- uv --directory /path/to/jadwigo/apps/cli run jw mcp serve
```

`claude mcp list` then shows `jadwigo`. `claude mcp remove jadwigo -s user` removes it.

Or check it in for a project as `.mcp.json`:

```json
{
  "mcpServers": {
    "jadwigo": {
      "type": "stdio",
      "command": "uv",
      "args": ["--directory", "/path/to/jadwigo/apps/cli", "run", "jw", "mcp", "serve"],
      "env": {
        "JADWIGO_BANK_DIR": "/path/to/jadwigo-bank",
        "JW_KHAN_CONVERTED": "/path/to/converted-pl.json"
      }
    }
  }
}
```

### Codex

```sh
codex mcp add jadwigo \
  --env JADWIGO_BANK_DIR=/path/to/jadwigo-bank \
  -- uv --directory /path/to/jadwigo/apps/cli run jw mcp serve
```

### Muse Code

Muse has no `mcp add` command. A stdio server is an entry under `mcpServers` in
`~/.config/muse/settings.json`, whose top level also needs `"schema_version": 1`. The entry's
field names are not confirmed yet: Muse does not warn on a wrong one.

```json
{
  "schema_version": 1,
  "mcpServers": {
    "jadwigo": {
      "transport": "stdio",
      "command": "uv",
      "args": ["--directory", "/path/to/jadwigo/apps/cli", "run", "jw", "mcp", "serve"],
      "env": { "JADWIGO_BANK_DIR": "/path/to/jadwigo-bank" }
    }
  }
}
```

## Draft a lesson

A lesson from the bank copies each question whole, its help included, and plays as copied. The
agent writes only what the bank does not have.

1. **Draft.** Call [`lesson_draft`](/mcp/lesson_draft/) with the parent's request. Pass every name
   the family uses in `names`. The tool replaces them before anything leaves the machine. Pass
   the `topic` in a few words, with no count, grade or name (`mnożenie`): the bank searches it.
   The draft stays on the server's machine under a `draft_id`, and a short view of it comes back.
2. **Write what is missing.** Each question's `you_write` lists it: the `twin`,
   `boost_by_mistake` for its `mistake_classes`, and any rung the copy leaves empty. Write it in
   the lesson's language. Change a copied part only when the parent asks, as a change in
   `changes`.
3. **Check.** Call [`lesson_check`](/mcp/lesson_check/) with the `draft_id` and your words by step
   id. Fix each error it lists by step id, and check again until it answers `ok` with a card.
4. **Import, then play.** The card's `next` names the import: `make lesson-import
   FILE=<lesson_file> ENV=dev` in the jadwigo checkout. The `play_path` exists only after it runs.

This guide is for anyone who calls a route that needs a credential: which one it takes, how to
send it, and what the API answers when it is missing.

A route takes one of 3 credentials: none, a Supabase Auth token, or the bank's read token. The
tables at the end list every route under its credential.

## Open routes: no credential

A child plays without signing in, so the routes a lesson needs take no token.

An attempt route is bound by its attempt id. Whoever holds the id may read and answer that
attempt. Only the reply that starts an attempt carries its id, so keep it safe and never log it.
An unknown id, or one from another pod, is `404`.

## Parent routes: a Supabase Auth token

An adult signs in to the app, and Supabase Auth runs the sign-in. However the adult signs in, the
result is a Supabase session, and its access token is what these routes take. Send it as a bearer
token:

```bash
curl https://app.jadwigo.pl/api/v1/me \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN"
```

- The token is a JWT signed with RS256, with the audience `authenticated`.
- No token, or one that fails verification, is `401` `NotSignedIn`.
- A token whose `exp` has passed fails verification. Refresh the session and try again.
- [`GET /api/v1/me`](/api/operations/getme/) reads the signed-in adult.
- On the first sign-in there is no account yet, and the parent routes answer `409`
  `AccountMissing`. Call [`POST /api/v1/accounts`](/api/operations/createaccount/) once. It
  makes the account and its pod. A repeat call returns the same records, so a double tap or a
  reload is safe.

## Bank routes: the bank's read token

The question bank is searched and read with a shared read token, not a Supabase token. The
[bank section](/api/operations/tags/bank/) of the API reference has both routes.

```bash
curl -X POST https://app.jadwigo.pl/api/v1/question-searches \
  -H "Authorization: Bearer $JADWIGO_BANK_READ_TOKEN" \
  -H "Content-Type: application/json" \
  -d @need.json
```

A question's body carries its answer key, so it is behind the same token:

```bash
curl https://app.jadwigo.pl/api/v1/questions/$QUESTION_ID \
  -H "Authorization: Bearer $JADWIGO_BANK_READ_TOKEN"
```

- A missing, malformed or wrong token is `401` `Unauthorized`, whatever the id.
- With the token, an unknown question id is `404`.
- When the server cannot reach the bank, the reply is `502` `BankUnavailable`. Try again later.
- The read token is shared. It is a stopgap until each caller gets a token of its own.

No error message ever names a token.

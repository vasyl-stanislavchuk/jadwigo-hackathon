The question bank grows by reading a new set of questions, having Meta models enrich it for
search, and letting it in only when the search test still passes.

<Diagram name="bank-pipeline" caption="The slice flow, from a source library to a gated index." />

## How it works

### Read and enrich

A reader turns each source library into the bank's own set pages. A Meta model then writes topics,
keywords and a summary for each set and question, so search can find them. A model writes only
under its own field, names itself on every field, and quotes the source for every claim. Code
drops a claim whose quote isn't in the source. [E4](/experiments/e4/) priced this at about $0.018
a set.

### Test before use

The team wrote test requests, called needs, from the curriculum, never from a source's own titles,
because a need written from a page's title would find that page and prove nothing. Each change to
the index runs against those needs, and a gate blocks it when a score drops past its limit
([E5](/experiments/e5/)).

### Licence first

Nothing is indexed before its licence is settled. Khan Academy's licence is CC BY-NC-SA 4.0, and
the owner ruled on it and on Alfik Matematyczny's terms first. A third library needs the same
ruling and its own credit line.

## Limits

- **The gate blocks the grown index today.** It finds more, but declines fewer requests it should
  decline ([E5](/experiments/e5/)).
- **No person has reviewed the enrichment.** Every field the models wrote is marked unreviewed,
  and the models' keywords barely agree with each other ([E4](/experiments/e4/)).
- **Size isn't measured.** Search hasn't been tried at thousands of sets.
- **The test needs show the gaps.** 127 of the 215 needs have no set that answers them yet.

All of Jadwigo's code lives in one repository: TypeScript apps and packages in one workspace, and
3 Python apps beside them, the command-line tool, the converter and print. A change to a schema
and every caller it breaks land in the same pull request.

<Diagram name="monorepo" caption="Imports point down. Nothing imports an app." />

## Layers

An app runs, and nothing imports an app. A domain package holds one job, such as grading, the
store or the AI engine, and has one public entry that other code imports. Domain packages may
import each other. `contracts` sits at the bottom and imports Zod and nothing of ours, so every
other part can depend on it.

A test reads this diagram's layers and every `package.json` in the workspace. It fails when an
import points up a layer, when anything imports out of `contracts`, or when a package that imports
or is imported sits in no layer.

## Rules the build enforces

Each of these is a check that runs on every pull request. Each has a test that plants a violation
to prove the check still catches it.

- **Apps import packages, never the reverse.**
- **No cycles**, and no import that doesn't resolve.
- **Test helpers stay in tests.** Only test files import the `testing` package.
- **Strict TypeScript.** Ids are branded types that only the contract parsers create, and an index
  into an array may be undefined.
- **The environment is read in one file per app**, its `config.ts`. An error type, a route path
  or an id prefix is written through its constant from `contracts`, never retyped.
- **No unused code.** An unused file, export or dependency fails.
- **No file over 1 MB.** Media and data go to their own stores, never into a commit.
- **Unit tests run offline.** A unit test fails on a network call, on real AWS and on an unpinned
  clock. Anything that needs those is an integration test.

## Every app

| App | What it is |
| --- | --- |
| `api` | The one Lambda: the router, `authorize()` and the routes. |
| `web` | The app at app.jadwigo.pl: the lesson player and the parent's screens. |
| `runner` | The AI engine's step host, a 2nd Lambda that drains the step queue. |
| `converter` | A Lambda that turns a PDF, DOCX or HEIC into 1 JPEG per page. |
| `print` | A Lambda that renders a lesson as a PDF to print. |
| `site` | The marketing site at jadwigo.pl. |
| `docs` | This site, docs.jadwigo.pl. |
| `cli` | The command-line tool for lesson authors, in Python: question search and its own MCP server. It talks to the API over HTTP. |

## Every package

| Package | What it holds |
| --- | --- |
| `contracts` | Zod schemas for everything that crosses a boundary: ids, records, the answer wire, the route table and the errors. |
| `core` | Grading, numbers and mastery, as pure functions. |
| `store` | The `Store` interface, an in-memory store and a Postgres store, and one contract suite both pass. |
| `jadwigo-ai` | The AI engine: a parent's chat becomes a lesson, one run per turn, every effect a run event. |
| `lesson-import` | Compiles a lesson file into lesson questions and a published version. |
| `lesson-kit` | The interaction families and the lesson blocks built on them. |
| `bank` | Code to read, search and import the question bank. |
| `api-client` | The typed client the web app calls the API with. Its types come from the contracts. |
| `ui` | The design tokens and the shadcn/ui primitives. See [Design system](/design-system/). |
| `copy` | Every string a person reads, in Polish and English. |
| `config` | The hosts and languages of every environment, in one place. |
| `analytics` | PostHog for the site and the app: the event catalogue, consent, the filter every event passes, and the scrubbed error report the API and the runner send. |
| `testing` | Fixtures, factories and the unit setup, for test files only. |

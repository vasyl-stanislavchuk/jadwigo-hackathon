Every route, record and error is defined once, as a Zod schema in the `contracts` package. The
route table, `ROUTES`, names each route's method, path, credential, body and reply. Everything
else, these docs included, is built from it or checked against it.

<Diagram name="contracts" caption="One table feeds the code, and the same table feeds these docs." />

## The code

- **The API** looks up each route in the table and parses the request and its own reply against
  the route's schemas. A handler never trusts its input.
- **The client** takes its types from the same schemas, so a changed field is a type error in the
  web app before anything runs.
- **The Terraform route list** names every route too, because API Gateway throttles each one and
  puts the JWT check on the parent routes. A check fails the build when that list and `ROUTES`
  differ, so a new route can't slip past its limits.

## The docs

The OpenAPI document is generated from the table and kept as a snapshot, and a test fails when
the two differ. So a contract change always shows in review. The docs build copies the snapshot
in, with the MCP tool list, the design tokens and the question-type catalog. A table the code can
make is generated from them, never typed by hand.

Before a publish, `check-dist` reads the built site. It fails when a page or a generated table is
missing, or when any page links into the source repository. A change to a route, an MCP tool or a
design token brings its docs in the same pull request.

## Every generated table

| What changes | Where it shows here |
| --- | --- |
| A route, its body or its reply | [API reference](/api/), from the OpenAPI document |
| An error type or its status | The table in [Errors](/guides/errors/) |
| Which credential a route takes | The tables in [Authentication](/guides/authentication/) |
| An MCP tool, its arguments or its reply | [MCP](/mcp/), from the MCP tool list |
| A design token | [Tokens](/design-system/tokens/), from the stylesheet |
| A question type | [Question types](/design-system/question-types/), from the lesson kit's catalog |

This run tests whether a model can write a parent's weekly report from facts that code computed,
without adding facts of its own. It's the last step of [the learning loop](/vision/learning-loop/).

<ExperimentResult id="e3" />

## Question

Can a model turn code's digest of a week into a short report a parent can use, that code can
check line by line?

## Setup

The 12 learners the team invented for [E1](/experiments/e1/) were loaded into a local database
only. Code folded each learner's answers into a digest: counts, the skills that moved, mistakes,
and the brief. `muse-spark-1.3-contributor` then wrote each report through the Meta API. Code
checked every report: each citation must be in the digest, no number may be invented, and no
level name may appear. Finally 3 blind judges on the same model scored accuracy, warmth and
usefulness from 1 to 5.

## Result

The judges rated the reports highly: 4.78 for accuracy, 3.94 for warmth and 4.44 for usefulness,
out of 5.

## What failed

- **Only 1 of 12 reports passed code's check.** The most common refusal was a shape slip: the
  model wrote a `text` field where the checker reads `answer`. Most reports failed on form, not on
  facts, but a parent would still get none of them as they stand.
- **The judges are the writer's own model.** An earlier panel on a different Meta model scored
  the same reports much lower: 3.85 for accuracy, 2.19 for warmth and 3 for usefulness. The high
  scores above are likely flattered.

## Cost

$0.16 for 48 calls. 1 report costs about $0.0046 to write, and $0.0135 with the 3 judges.

This experiment is for a judge choosing the voice a parent hears: code digests each invented
learner's work, 1 model writes the narrative, and a blind panel scores accuracy, warmth and use
to a parent.

<ExperimentResult id="e3" />

The 12 invented learners of [E1](/experiments/e1/) were loaded into a local `jadwigo` database
only, and `make dream` ran on each: code folds the evidence and computes the digest (counts,
skills that moved, mistakes, the brief, proposals), and the narrative starts out empty.
Following `/jadwigo-report-write`, `muse-spark-1.3-contributor` wrote each narrative through
the Meta API and the product ledger. Code then scored every narrative with `narrative_check`
(citations all in the digest, no invented numbers, no level names), and 3 blind judges on the
same contributor model scored accuracy, warmth and usefulness from 1 to 5, never told who wrote
what they read.

<Diagram name="dream" caption="Code digests, AI narrates, the parent decides." />

The run's first pass also wrote each narrative with `muse-wonder` and judged both with a wonder
panel, before the owner's rule that scripted calls use the contributor models on the API. Those
results are kept under `detail.wonder_comparison` in the JSON, and compared briefly below. What
this seeds is the scheduled dream (`dl-e8ov.5.49`), the weekly parent report, and evidence for
the report's model choice.

A brief comparison with the wonder run kept in the JSON:

- As writers, the 2 models were close against code's checker: 1 of 12 contributor narratives
  with no findings in this run, 2 of 12 for wonder. The most common refusal for both was the
  same shape slip: the standing answers came back with a `text` field where the schema's
  checker reads `answer`, so several narratives fail on form, not on facts.
- As judges they were not the same. Contributor judges scored the contributor's narratives 4.88
  for accuracy, 3.61 for warmth and 4.3 for usefulness. The wonder panel had scored the same
  writer 3.85, 2.19 and 3, and wonder's own narratives 4.37, 2.5 and 3.2. A model judging its
  own words reads warmer and more useful to itself; the numbers here say by how much.
- One headline, 2 voices, for the steady learner. Contributor: "Dziecko ćwiczyło mnożenie i
  ortografię przez 16 dni, część mnożenia wymaga uwagi." Wonder: "Dziecko ćwiczy mnożenie i
  ortografię, a mnożenie przez 2, przez 3, przez 5 i przez 7 wymaga uwagi." Both stay inside
  the digest; neither names a level.

## Every cost, per learner

The ledger prices each call, so the run gives a cost per learner, not just a total. A judge
call is experiment quality control, not something the product would run for a family; the
product's own cost is the narrative call alone. Making the lesson itself is not in these
numbers: [E6](/experiments/e6/) measures the photo-to-lesson path.

| What | Cost | From |
| --- | ---: | --- |
| Folding 3 weeks of evidence (E1) | $0 | local code, no model |
| Drawing the next lesson (E2) | $0 | a local scan of the bank |
| 1 optional judge of that draw | $0.0025 | the ledger, per call |
| Writing 1 report narrative | $0.0043 | the ledger, 47 calls |
| Judging 1 narrative, blind, 3 judges | $0.0086 | the ledger, per call |
| 1 learner's weekly report, as a product runs it | $0.0043 | 1 narrative, no panel |
| 1 learner's weekly report, with this panel | $0.0129 | narrative plus 3 judges |

So a learner who gets a report every week costs about $0.017 a month in model calls, about
$0.05 with the full judging panel each week, and $0 for their lessons' draws and folds. Even a
learner with a report a day stays under $0.15 a month. The cost question for learner knowledge
is not the model's price; it is whether the words are right, which is what the findings above
measure.

This experiment is for a judge who wants to see learner knowledge move: 12 invented learners with
distinct profiles answer for 3 weeks, and code folds every attempt into mastery levels and review
dates.

<ExperimentResult id="e1" />

Each learner is a small behaviour, not a script: a hidden skill level per topic that grows with a
clean first try, fades over a gap, and is sampled on every answer. The clock is pinned (from
2026-10-12, seed 20261012, 21 days), so a re-run gives the same cohort byte for byte, apart from
the wall time and the commit the run records. The 10 skills are real catalogue codes:
multiplication rows 2 to 7 and 4 Polish spelling skills. The fold, the FSRS due dates and the
brief are the product's own code in `packages/core` (`foldLearner`, `brief`); no model ran and
nothing was written to a database, so
the cost is $0.

<Diagram name="learner-knowledge" caption="Evidence in, a level and a due date out, then a brief." />

This cohort is the shared starting point of this lane: E2 draws each learner's next lesson from
these briefs, and E3 dreams a parent report over the same evidence. As product work it seeds the
learner knowledge base (`dl-e8ov.5`) and the parent progress view, where these levels are never
shown by name, only in words a parent can use.

3 readings a judge can check in the JSON:

- The fold separates the profiles as written: steady and perfectionist end with 4 skills at
  mastered, while forgetful keeps only 1 and has 9 skills flagged for reteach.
- Being right with help does not lift a level. Help-heavy answered 104 times and still has 5
  skills at attempted.
- A miss in a skill's last 2 attempts flags it. After 3 weeks 79 of the 120 skill rows carry that
  flag, which is why so many briefs read reteach first.

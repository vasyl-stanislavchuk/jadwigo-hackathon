This run tests whether the bank's search test catches a change that makes search worse. It's the
gate behind [growing the bank](/vision/growing-the-bank/).

<ExperimentResult id="e5" />

## Question

When the bank grows, does its golden-set gate stop an index that got worse in a way that matters?

## Setup

A golden set is a frozen list of requests with known right answers. The team wrote the bank's 215
requests, called needs, from the Polish grade 3 curriculum, never from Khan's own titles. 3
independent model passes labelled each one, and the set was split once into 150 tune needs and 65
holdout needs. The gate blocks any change that drops a metric past a written limit. This run
scored hybrid search against the current index: 411 sets, up from the 143 the baselines were
scored on.

## Result

The gate blocked, which is its job. Search finds more than before: recall in the top 10 went from
0.8611 to 0.9167. But it declines fewer of the requests it should decline.

## What failed

- **The grown index is blocked.** Of 9 needs the bank can't serve, it now declines 3 instead of
  5. That's a drop of 22.23 points against a limit of 15. More sets means more near misses worth
  returning, and a person has to decide whether those needs are still gaps.
- **The holdout check couldn't judge at all.** Its baseline was scored on an older version of the
  golden set, so the 2 runs measured different questions. Updating that baseline is left undone on
  purpose.
- **The labels are models' labels** on needs the team wrote, not a teacher's.

## Cost

About $0.08 of search and rerank calls, estimated because neither service reports usage. No Meta
model was called.

# apps/docs

The living docs at docs.jadwigo.pl: Astro and Starlight, static output, English. The API, MCP and
design-system pages are generated from the code at build time and never committed (`dl-5ssh.90`,
decision `jadwigo-platform/notes/2026-10-29-jadwigo-s-docs-are-a-starlight-site-at-docs-jadwigo-pl-generated`).

- **Not here:** Marketing pages (`apps/site`), the live component gallery (app.jadwigo.pl/playground/system,
  which the design-system pages link to rather than embed), and decisions (the md context brain).
- **Owner:** the platform workstream (`docs/workstreams/platform.md`). **Filled by:** `dl-5ssh.90.6`, then
  `dl-5ssh.90.7` (API), `dl-5ssh.90.8` (MCP), `dl-5ssh.90.9` (design system), `dl-5ssh.90.13` (architecture).
- **Imports:** packages: `contracts`, `config`, later `lesson-kit` and `ui`. Never another app.
- **Public surface:** `src/index.ts`. Other files are private to this package.
- **Test:** `bunx turbo run lint typecheck test build --filter=./apps/docs`, then `bun run check:dist`.
- **Deploy:** the owner publishes it (`dl-5ssh.90.12`). A merge deploys nothing.

## How it is laid out

- `src/content/docs/`: every page, as `.md` or `.mdx`, in Starlight's `docs` collection
  (`src/content.config.ts`). The file's path is its slug: `guides/errors.mdx` is `/guides/errors/`.
- `src/index.ts`: the hosts and `SIDEBAR`. A page joins the sidebar by its slug there; a new section
  is a new group. A slug with no page fails the build.
- `src/lib/`: pure functions that turn the code into tables (`errors.ts` from `ERROR_STATUS`,
  `access.ts` from `ROUTES`), each with a test. `src/components/`: the `.astro` tables an `.mdx`
  page imports.
- `src/lib/check-dist.ts` and `scripts/check-dist.ts`: what the built `dist/` must carry before it
  is published, and that no page links into GitHub.
- The API reference (`/api/`) is generated by `starlight-openapi` from `public/openapi.json`, which
  `scripts/prepare.ts` writes before every build: the snapshot `packages/contracts/openapi.json` plus
  the server (`hosts.prod.app`) and the tag descriptions (`src/lib/openapi.ts`). It is served as is
  at `/openapi.json`. No page under `src/content/docs/api/` is written by hand.
- `src/guides.test.ts`: every `/api/...` path a page names is in `ROUTES`, and every link into
  `/api/` is a page the reference builds (the links validator sees only content pages).
- `public/openapi.json` and `public/mcp-tools.json` are copied in at build time from
  `packages/contracts/openapi.json` and `apps/cli/mcp-tools.json`, and gitignored. `turbo.json`
  lists both snapshots as build inputs, since `--affected` does not follow a plain file read.

## Rules here

- **Live docs:** a change to a route, an MCP tool or a design token brings its docs in the same PR.
  A table the code can make is generated from it, never typed by hand.
- **Self-contained:** no page links into the GitHub repo (the owner, `dl-5ssh.90`). `check:dist` fails one.
- A broken internal link fails the build (`starlight-links-validator`).
- `llms.txt`, `llms-full.txt` and `llms-small.txt` are built for agents (`starlight-llms-txt`).
- Hosts come from `packages/config`, never a hard-coded domain in code. Route paths and error types
  come from `packages/contracts`.
- Writing: digits for numbers, short sentences. Never a family member's name or real learner data,
  not even in an example.
